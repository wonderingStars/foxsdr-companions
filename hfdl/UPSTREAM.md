## Why parts are C++ and not C
The build must be MSVC (Visual Studio 2022, x64). MSVC's C compiler has no `float complex`; dumphfdl and liquid-dsp are written
on it. The signal-processing files (`hfdl`, `fastddc`, `libcsdr`, `libcsdr_gpl`, liquid-dsp objects, FFT) are therefore C++ using
`std::complex<float>`. The protocol layers (MPDU, LPDU, HFNPDU, SPDU, ACARS glue, system table, caches, formatters) contain no
complex arithmetic and stay C, compiled by MSVC's C compiler.

## Changes made (everything that is not byte-for-byte upstream)
Protocol layer (C):
* **No threads.** `util.c/h`: thread/barrier helpers removed. `globals.c/h`: pthread mutexes removed, the lock macros are no-ops.
  `pdu.c/h`: the decoder thread and its `GAsyncQueue` are replaced by synchronous decoding: `pdu_decoder_queue_push()` decodes the PDU
  and calls a sink for every LPDU/SPDU tree. `output-common.h` reduced to the formatter descriptor types.
* **Reproducible output.** There is no wall clock: `util.c` has a sample clock (`helper_now()`, `helper_now_us()`, start time from
  `--start-time`, default 0) and the `time(NULL)` calls in `ac_cache.c`, `cache.c`, `ac_data.c`, `position.c` use it, so cache expiry
  and the date filled into partial timestamps depend on the input only.
* `util.h`: `NEW()` without the parenthesised declarator (MSVC rejects it), `LIKELY/UNLIKELY` already fall back for non-GCC.
* `systable.c`: `#include "miniconfig.h"` instead of `<libconfig.h>`.
* `fmtr-text.c`: `time_t` copy of `tv_sec` (32-bit `long` in `struct timeval` on Windows), zone name "UTC" (the MSVC runtime prints an empty one).
* `globals.c`: `DUMPHFDL_VERSION` (upstream generates `version.c` at build time).
* New: `config.h` (replaces the CMake-generated one), `compat/` (shims for `sys/time.h`, `unistd.h`, `strings.h`, force-included
  `hfdl_compat.h`).

DSP (C++, `float complex` -> `std::complex<float>`):
* `hfdl.cpp` <- `hfdl.c`: same framer (A1/A2/M1/M2 correlation thresholds, equalizer training, Costas loop, symbol timing, noise floor,
  signal level, de-interleaving, soft Viterbi, descrambler); the per-channel thread and `block.c` plumbing replaced by one
  synchronous receiver `hfdl_rx` that owns the shared forward FFT (upstream's `fft.c`, overlap-save) and the channels, run in command-line
  order for each FFT block; frame timestamps come from the sample clock; the liquid-dsp 1.6-versus-older descrambler constants are
  fixed to the >= 1.6 values (`0x4001` / `0x4d4b`, upstream's own branch for current liquid-dsp); `statsd`, data dump and the noise-floor
  statistics thread removed; variable-length arrays became `std::vector`.
* `fastddc.cpp`, `libcsdr.cpp`, `libcsdr_gpl.cpp`, `csdr.hpp` <- `fastddc.c`, `libcsdr.c`, `libcsdr_gpl.c` and their headers:
  same algorithms, the FFT plan objects replaced by `Fft` (`fft.cpp`).
* `lq.hpp`, `lq.cpp`: liquid-dsp port. `msresamp_crcf` is reduced to its zero-half-band-stage case: dumphfdl first decimates in the
  frequency domain by `compute_fft_decimation_rate()` so that the rate fed to `msresamp_crcf` is always in 5400..10800 S/s, the
  resampling ratio is in (0.5, 1], and liquid-dsp then uses its arbitrary-rate resampler only. `symsync_crcf_create_kaiser`'s `_beta`
  argument is not used by liquid-dsp either. No SIMD dot products: results agree with a liquid-dsp build to float rounding, not bit for bit.
* `miniconfig.c/.h`: new code replacing libconfig for `systable.c` (read, write, lookup).

Helper front end (new): `helper_main.c` (protocol v1 argument parsing, hello line, `--foxsdr-helper-info`, cs16/cf32 input,
JSON line assembly, one-line text form), `redact.c` (`--hide-ids`), `hfdl.helper.json` (manifest).
Differences in behaviour against upstream dumphfdl: no `--soapysdr`/`--iq-file` (input is stdin), channels are given as offsets in Hz
from the I/Q centre instead of kHz frequencies, no outputs other than the JSON line, `--system-table-save` and the Basestation
database (`--bs-db`) are not offered, minimum sample rate 10800 S/s (see README).
