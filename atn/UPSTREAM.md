## Changes to upstream files (each one, and why)

1. `src/asn1/asn_system.h` - MSVC: (a) `snprintf`/`vsnprintf` are no longer redefined as `_snprintf`/`_vsnprintf`
   (those do not NUL-terminate on truncation) except for MSVC older than 2015; (b) the block that typedef'ed
   `int8_t`..`uint32_t` itself (clashes with `<stdint.h>`) is replaced by `#include <stdint.h>` and a `ssize_t` typedef;
   (c) `isnan`/`copysign`/`ilogb` remaps only for MSVC older than 2015.
2. `src/asn1/asn_internal.h` - `__attribute__((unused))` on `ASN__STACK_OVERFLOW_CHECK` is not used with MSVC.
3. `src/dumpvdl2/avlc.h` - `avlc_addr_t`: the `status` and `type` bit-fields were `uint8_t` next to a `uint32_t addr:24`;
   MSVC starts a new storage unit when the base type changes, which moved them out of the 32-bit word that `val`
   overlays (addresses decoded wrongly). All three are `uint32_t` now. (All other bit-field structs in the copied
   files use one base type; checked.)
4. `src/dumpvdl2/avlc.c` - `avlc_format_json()`: dumpvdl2 2.7.0 prints the send sequence number as `"rseq"` and the
   receive sequence number as `"sseq"` for I frames (swapped; its text output is right). Corrected, and the test pins
   the corrected values. This looks like an upstream bug and could be reported there.
5. `third_party/libacars/libacars/reassembly.h` - includes the compat `<sys/time.h>` on MSVC too instead of `<winsock.h>`
   (no Winsock is linked or used).
6. `src/dumpvdl2/config.h` and `third_party/libacars/libacars/config.h` replace the CMake-generated headers of the
   two projects (nothing optional enabled; Windows `lfind()` prototype).

## New files (written for this helper, GPL-3.0-or-later)

`src/main.c` (the helper protocol, input parsing, event output), `src/stubs.c`, `compat/` (small stand-ins for
`glib.h`, `gmodule.h`, `pthread.h`, `unistd.h`, `sys/time.h`, `arpa/inet.h`, `libacars/asn1/*` forwarders, and
`foxsdr_win.h`, the forced include that supplies `ssize_t`), `CMakeLists.txt`, `atn.helper.json`, and `tests/`.
Behaviour differences from `dumpvdl2`: no per-burst metadata header (time, frequency, signal level - an AVLC hex line
has none), no address databases, no file/UDP/ZeroMQ output, the text rendering is the protocol tree only.

## What the tests prove, and what they do not

`tests/make_frames.py` builds 20 frames byte by byte (AVLC addresses and FCS, X.25 packets incl. fast select / SNDCF /
fragments, CLNP full and LREF-compressed, COTP DT / DR, ES-IS, IDRP, XID) from the layouts in the standards - not by
running dumpvdl2's decoder. The application PDUs (`tests/apdus.txt`) were made with the asn1c PER *encoder* bundled with
dumpvdl2 (`tests/testgen.c`): a CM logon request, a CM abort, CPDLC DM0 / UM0 / user abort, an ADS-C v2 user abort, and an ACSE AARE inside an X.225 Short Accept SPDU; the one-byte CPDLC abort was
also checked by hand (`05` = extension bit 0, choice index `00`, enumeration `0101`). The decoder then recovers the flight
identification, message numbers, timestamp and message elements that were put in. All of it is synthetic: **nothing was
decoded from a real over-the-air frame.** Not exercised: ADS-C reports and contracts (only the user-abort PDU), ACSE AARQ, IDRP
OPEN/UPDATE, the CLNP segmentation part, ES-IS ESH, COTP CR/CC, the security label. They are upstream code, compiled in.
